# Reflection: Muhamad Rifqi bin Zulkiflie

My part was the customers: CustomerState, the Customer class and RegularCustomer for Stage 1, then the VIP and Critic for Stage 2, the Happy Hour recovery for Stage 3, plus the class diagram. Before this I had only done Python in CT2001, so Java and GitHub were both new to me. My work laptop does not allow installing Git, so I ended up doing everything in GitHub Codespaces and picked up branches and pull requests as I went. The part that made OOP click for me was the abstract class. I wrote loseSatisfaction() once in Customer, and each type just says how much it loses, so when the VIP and Critic came in Stage 2, nobody had to touch the game loop. One mistake I made was copying a method and forgetting to change the field name, so the ready-to-pay turn was saved in the wrong place. Java did not complain, so now I always check with real numbers. If I did it again, I would start the class diagram much earlier and write the checks together with the code.
